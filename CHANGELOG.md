# Changelog

## Unreleased

- Require Home Assistant 2026.10.0b0 or later.
- Build the machine's device info without dict-style item assignment, ready for Home Assistant 2026.11's dataclass `DeviceInfo`.
- Migrate LLM tools to ToolResult with explicit failure flags and tool metadata, preserving existing response payloads.
- **Breaking:** rename every LLM tool to Home Assistant's `<domain>__` tool name convention, dropping the now-redundant `xbloom` from each name: e.g. `get_xbloom_status` → `xbloom__get_status`, `pour_xbloom` → `xbloom__pour`, `execute_xbloom_recipe` → `xbloom__execute_recipe`. Update any conversation prompt that names the old tools.
- `pod_detected` now carries the pod / recipe card's bean info and recipes, looked up from XBloom's cloud by the tag id (no account needed).
- Cloud recipe import no longer carries bypass volume/temperature from a recipe whose bypass is switched off.
- The state sensor now reports `sleeping` while the machine is asleep (it sleeps ~10 min after the last activity, even while connected), and returns to its real state when a pod insert or a button press wakes it. A sleeping machine no longer counts as activity for the idle disconnect timeout.
- The weight sensor now reads unknown instead of 0.0 g while there is no Bluetooth link (idle standby, out of range), so it can no longer be mistaken for an empty scale.
- The weight sensor also reads unknown while the machine sleeps. Asleep, the machine keeps reporting a fixed 50 g with nothing on the scale, which used to show up as a real reading.
- A unit or water-source change sent while the machine sleeps is now retried until the machine wakes and accepts it (up to 3 sends, 1.5 s apart), instead of being dropped.
- Arming a recipe (and every other machine action) while the machine sleeps no longer fails with "No ACK for 8022" when the sleeping machine drops the first command; the action is resent the same way, up to 3 times, 1.5 s apart.
- The state sensor no longer sticks at `no_beans` after the machine leaves its no-beans screen (e.g. after a cancel). It now follows the machine's screen, as the official app does; the `no_beans` error event still fires once.
- A machine status report that arrives in the same Bluetooth notification as another message is no longer missed. A missed "starting" report made a brew that had started fail with "machine is waiting for confirmation on its own screen".
